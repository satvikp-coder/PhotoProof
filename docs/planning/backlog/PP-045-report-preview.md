## Summary

A Report tab on the result page that renders the structured report (PP-046) as HTML and
offers downloads (PDF from PP-047, JSON, and the manifest).

## Problem Statement

Reports are generated by core services, but users need to preview them before sharing
and to export them easily.

## Objective

A faithful HTML preview, identical in content to the PDF, with download buttons.

## Technical Background

Render the same report model with a screen stylesheet (preview) and a print stylesheet
(PDF), so the content cannot diverge.

## Functional Requirements

- Preview tab with the table of contents.
- Downloads: PDF, report JSON, manifest JSON, with file names that include the run ID.
- A "what this report does not show" box, always visible.

## Technical Implementation

`WebKit/pages/report.*`; the reporting service API from PP-046.

## Integration Requirements

PP-046 (model and HTML) and PP-047 (PDF).

## Security and Edge Cases

`Content-Disposition` with sanitized file names. No originals embedded.

## Testing Requirements

The preview matches the report model (snapshot). Download endpoints return the correct
types.

## Acceptance Criteria

- [ ] The preview and PDF are generated from the same report model.
- [ ] All three downloads work and use sanitized file names.
- [ ] The limitations box is always present.

## Expected Outcome

Easy, consistent report sharing.

## Documentation Requirements

The user guide (reports).
